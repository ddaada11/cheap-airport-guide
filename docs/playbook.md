# 落地手册：从 0 到有返佣的 90 天

> 📎 **先读 [`plan.md`](./plan.md)**：那份讲的是「信息从哪来、怎么保证新鲜」，是这套东西的发动机。
> 本文讲的是「拿到信息之后，按什么顺序做」，是传动轴。两份配合看。

> 前置认知：你做的不是「网站」，是**一个会被搜索引擎长期收录的内容资产**。
> 它的价值 = 关键词覆盖 × 内容可信度 × 存在时长。三样都能用工程手段加速，唯独「时长」不能。

## 阶段 0 · Day 0（半天）：把变现链路打通

**没有邀请码之前，写任何内容都是白写。**

1. 选 5~8 家机场，注册账号，**申请推广/分销（affiliate）**。
   - 大部分面板（v2board / xboard）后台自带「推广链接」页，形如 `https://域名/auth/register?code=XXXX`。
   - 部分机场需要开工单申请，问清楚三件事：**返佣比例、结算周期、结算门槛**。
   - 优先选：开业 2 年以上、有公开 aff 后台、支持循环返佣（续费也返）的。
2. 建一个表格记录：机场名 / 邀请码 / 返佣比例 / 结算方式 / 联系客服方式 / 你的账号。
3. **自己先买一个月**。这是后面所有「实测」内容的来源，也是你唯一能理直气壮写「我在用」的底气。

> 别一次挂 15 家。**5~8 家**是甜点：足够分散跑路风险，又不会让每个机场的实测记录都变成糊弄。

## 阶段 1 · Day 1-3：仓库上线（本目录已就绪）

### 1. 改数据

```
data/site.mjs       ← 仓库名、description、topics、通知、故事、立场声明
data/airports.mjs   ← 机场列表（唯一需要长期手工维护的文件）
```

把 `示例云 A/B/C` 换成你真实的机场，`AFF_CODE_X` 换成你的邀请码。

### 2. 出稿并自检

```bash
npm run verify        # 静态校验 + 生成 README
npm run check -- --net   # 额外探测注册页是否可达
```

`check.mjs` 会拦住三类致命错误：**URL 里没带邀请码**（白干）、**日期格式错**（表格错位）、**域名重复**。

### 3. 建仓库

```bash
git init
git add -A && git commit -m "init: 机场推荐列表"
gh repo create <repo-name> --public --source=. --push
```

仓库设置三件事（**这是流量入口，比 README 更重要**）：

| 位置 | 怎么填 |
| --- | --- |
| 仓库名 | 短 + 一个高价值词，如 `cheap-airport-guide`。别用一长串关键词，像垃圾站 |
| Description | 用 `data/site.mjs` 里的 `description`，≤350 字符，关键词堆满 |
| Topics | 12 个，从 `site.mjs` 的 `topics` 复制。**这是 GitHub 搜索的第二入口** |
| Website | 填你的独立站或 TG 频道（有就填，没有留空） |
| LICENSE | 内容型仓库用 `CC-BY-4.0` 或 `MIT`，别用无 license（会降低可信度） |

### 4. 打开 GitHub Pages（可选但强烈建议）

仓库 Settings → Pages → Deploy from branch `main` / root。
README 会被渲染成 `https://<user>.github.io/<repo>/`，**多一个独立可收录的 URL**，且不依赖 GitHub 仓库页的排名。

## 阶段 2 · Day 4-14：内容资产

目标：**首屏 30 秒内让读者相信「这个人是真的在用」**。

按 `data/keywords.md` 的优先级填内容，顺序不能反：

1. **作者故事**（150~250 字）：你被哪家坑过、损失多少、怎么转向按月付费。**具体数字比形容词有用**。
2. **立场声明**：不接受投稿、不接受付费置顶、防冒充。这三句是信任杠杆。
3. **购前须知 + 标记体系**（🟨🔥🔒✋📜）：主动给合作方打差评，是最高级的信任建设。
4. **机场 vs VPN 科普**：解释「国内大部分 VPN 是套壳机场」，直接抬高你的专业度。
5. **表格**：开业日期 / 类型 / 倍率 / 套餐 / 优惠券。**优惠券是转化加速器**，每月更新。
6. **排障 FAQ**：订阅更新失败、DNS、IPv6、客户端版本。这部分决定读者会不会收藏。

**不要做的：**
- ✘ 复制别人的段落（会被判定重复内容，且显得假）
- ✘ 写「测速图」（截图随时过期，且暴露你在编）
- ✘ 给机场排名（一旦排名就会被同行针对，且读者只买第一名）

## 阶段 3 · Day 15-30：分发（流量从这来）

按投产比排序，前三个必须先做：

| # | 渠道 | 具体动作 | 预期 |
| --- | --- | --- | --- |
| 1 | GitHub 搜索 | 元数据三层填满 + **每 2~3 天一次 commit**（改优惠券、改通知日期都算） | 站内长尾词进入前 3 页 |
| 2 | 搜索引擎收录 | Google Search Console / Bing Webmaster 提交 `github.io` 站点地图；在 description 里保留可被索引的独特长句 | 2~6 周开始有自然流量 |
| 3 | 镜像同步 | Gitee / GitLab / GitCode 各建一份镜像，README 顶部互链 | 覆盖国内可访问的入口 |
| 4 | 导航站 / 聚合站 | 提交到「机场导航」「TG 导航」类站点；主动联系站长互换链接 | 稳定外链 |
| 5 | 长文平台 | 知乎「机场怎么选」、掘金/V2EX 技术贴（讲协议不讲推广）、小红书（讲避坑） | 引流到仓库 |
| 6 | TG 频道 | 建一个频道，同步「今日优惠券」「跑路通报」 | 复访率最高 |
| 7 | B 站 / 短视频 | 「我被机场坑了 400 块」类避坑视频，简介放仓库链接 | 爆发式，但不可控 |

**分发铁律：不要刷 star、不要买 star。** 一旦被判定异常增长，仓库会从搜索结果里消失，前面所有工作归零。真实增长路径是：内容被转载 → 有人 fork → fork 被索引 → 带来新访问。

## 阶段 4 · Day 31-90：矩阵与放大

单仓库的天花板很明显（一个仓库只能占一组关键词）。这一步做三件事：

1. **拆仓库**：主仓库做「机场推荐」，另开 2~3 个垂直仓库，各打一个场景：
   - `clash-config-guide` —— 只讲客户端配置（Clash Verge / FlClash / 小火箭），文末带机场链接
   - `chatgpt-access-guide` —— 只讲 AI 工具访问，场景词蓝海
   - `airport-troubleshoot` —— 只做排障 FAQ，长尾问题词收割机
2. **独立站**：GitHub Pages 或 Cloudflare Pages 搭一个静态站，域名带关键词。**独立域名权重 > 仓库页**，且不怕仓库被下架。
3. **数据化**：把 `data/airports.mjs` 扩成真正的实测数据集（延迟、倍率、解锁、客服响应时长），生成对比表。**这是大仓库明确说「不做」的部分**，也是你唯一能形成壁垒的地方。

## 长期节奏（跑起来之后）

| 频率 | 动作 | 耗时 |
| --- | --- | --- |
| 每 2~3 天 | 改一条通知/优惠券 → `npm run build` → commit | 10 分钟 |
| 每周 | `npm run check -- --net` 巡检全部注册页，挂了立刻标 🟨 | 5 分钟 |
| 每月 | 对账返佣；更新优惠券有效期；删过期券 | 30 分钟 |
| 每季 | 按 GitHub 搜索下拉词更新 description / topics；补 1~2 家新机场 | 1 小时 |
| 事件驱动 | 机场跑路 / 大面积通报 → 当天发通知 + 标 🟨 + 移入「已移除」 | 20 分钟 |

## 指标看板（每周记一次）

| 指标 | 怎么看 | 健康值 |
| --- | --- | --- |
| 注册点击数 | 短链后台 / 机场 aff 后台 | 周环比不下降 |
| 注册转化率 | 注册数 ÷ 点击数 | > 15% |
| 付费转化率 | 付费数 ÷ 注册数 | > 8% |
| star 增速 | 自然增长 | 前 3 月 5~20/周属正常 |
| 搜索收录页数 | `site:github.io/<repo>` | 持续增加 |
| 返佣收入 | 机场后台 | 第 3 月应能覆盖你的自购成本 |
