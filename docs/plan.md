# 执行方案：把「低价机场」做成一条可复用的信息生产线

> 一句话：**这个项目的瓶颈不是写文章，是「信息的新鲜度和密度」。**
> 别人手抄 30 家、两个月不更新；你要做到「一次命令刷 200+ 家、价格来自面板官方接口、每 GB 成本自动算」。
> 内容只是数据的渲染结果。数据层做对了，内容生产就变成 10 分钟一次的机械动作。

---

## 一、先看清：低价机场这个选题，到底缺什么

| 你以为缺的 | 实际缺的 | 为什么 |
| --- | --- | --- |
| 更多机场名字 | **价格 + 流量 + 线路 的结构化字段** | 只有名字的清单，读者看完还是不知道该买哪家 |
| 更便宜的机场 | **「便宜」的可计算定义** | 不说每 GB 成本，2 元 100G 和 8 元 1000G 谁便宜没人算得出来 |
| 更多评测文章 | **可交叉验证的价格来源** | 抄来的价格过期了会被读者当场打脸 |
| 更多流量 | **自己的邀请码** | 你抄的每个链接都带别人的码，流量再大也结算不到你账上 |

**结论**：把力气全部压在「结构化 + 可刷新」上，不要去卷文笔。

---

## 二、三条信息线（这是整个方案的核心）

```
线 1  清单型源  ──→  机场名 + 价格 + 流量 + 优惠码 + 线路 + 评分 + 节点数
线 2  长文型源  ──→  机场名 + 价格(标题里) + 官网域名 + 邀请码
线 3  面板接口  ──→  官网当前的套餐表（官方值，最可信）
                    ↓ 按「名字归一化」合并
               data/shortlist.json  ← 一张表决定所有内容
                    ↓
        README / 独立站 / TG 推送 / Excel 选品表
```

为什么必须分开：

- **线 1 的源里没有官网链接**。机场查、机场YYDS、clashmetahub 这些「品牌库」，表格里全是指向自己站内的跳转链接。你从它们的 README 里抓域名，只会抓到导航站自己。
- **线 2 的源里没有结构化价格**。价格写在标题括号里（`## 一、吹雪云 (4/月512G)`），得按格式解析，但它同时给了域名和邀请码。
- **线 3 是唯一能拿到「今天真实价格」的地方**。v2board / xboard 面板都暴露了未登录可访问的接口：
  ```
  POST /api/v1/guest/plan/fetch
  → { data: [ { name, month_price, quarter_price, year_price, transfer_enable, ... } ] }
  ```
  价格单位是分，`transfer_enable` 单位是字节。这一条打通，你就有别人没有的东西：**价格能自动刷新**。

## 三、已经落地的流水线（本目录）

```bash
npm run data      # 一键全跑：harvest → enrich → discover → merge
npm run probe     # 问面板要真实套餐价（在你自己的网络跑，机场域名在部分网络不可达）
npm run select    # 按规则挑品 → data/airports.draft.mjs
npm run select -- --commit && npm run build   # 出稿 README.md
npm run xlsx      # 出 Excel 选品表（给人看的版本）
```

| 脚本 | 干什么 | 产出 |
| --- | --- | --- |
| `harvest.mjs` | 把 18 个源的原文快照到 `ref/sources/` | 证据留档，价格对不上能回溯是哪天的哪一版 |
| `enrich.mjs` | 表格型 + 长文型双解析器，抽 12 个字段 | `data/facts.json` |
| `discover.mjs` | 从带注册链接的源里捞域名，聚合同一家的备用域名 | `data/pool.json` |
| `merge.mjs` | 名字归一化后合并事实与域名，算每 GB 成本、价格分层 | `data/shortlist.json` + `.csv` |
| `probe.mjs` | 打面板接口拿官方套餐表，写回最高优先级价格 | `data/probe.json` |
| `select.mjs` | 按「低价」规则挑品，保留人工字段 | `data/airports.draft.mjs` |
| `build.mjs` | 数据 → README 长文 | `README.md` |
| `make_xlsx.py` | 分 sheet 出选品表 | `data/机场选品表.xlsx` |

**价格优先级**：`probe`（面板实测） > `源观测`（多源取最低）。表里每行都标了来源，发布前一眼能看出哪几条需要自己核。

## 五、变现前置：先把自己的码换上（不做这步，后面全是白干）

`data/shortlist.json` 里的邀请码，**全部来自同行仓库作者**。原样挂出去，读者注册付费都记在别人账上。

```jsonc
// data/my-aff.json
{
  "aff": {
    "xn--9kqs1lo79d.com": {
      "code": "你的码",
      "url": "https://你的注册链接?code=你的码",
      "rate": "首单 20% / 续费 10%",
      "settle": "月结，满 100 提现"
    }
  }
}
```

填完之后 `npm run merge`，`shortlist` 里 `isMine` 变 `true`，`select` 出来的条目就不带 🔁 标记了。

**选哪几家去申请**：不要贪多，`select` 默认挑 ≤15 元的，从中选 **5~8 家**：

- 至少 2 家 ≤5 元档（做「极致低价」标签，负责拉新）
- 至少 2 家 5~10 元档（主力，转化率最高）
- 至少 1 家 10~15 元档（做「加钱上专线」的对照）
- 每家都必须：开业 2 年以上 + 有公开 aff 后台 + 支持续费循环返佣

## 六、内容生产：按价格档写，不按机场写

这是最容易做错的地方。**逐家写评测 = 写不完 + 读者记不住**。按「预算档」写，一个档一篇：

| 篇目 | 标题模板 | 用到的字段 | 转化逻辑 |
| --- | --- | --- | --- |
| 主表 | 2026 低价机场推荐：N 家按月付费实测 | 全字段 | 落地页，所有链接入口 |
| 分档 1 | 5 元以内的机场能买吗（附 3 家实测） | minMonthly ≤5 | 低预算人群，量大 |
| 分档 2 | 5–10 元档怎么选：每 GB 成本横评 | pricePerGb | **主力转化** |
| 分档 3 | 大流量机场：1000G 以上月付对比 | gb ≥1000 | 下载党 |
| 场景 1 | 只看 YouTube/Netflix 该买哪家 | 流媒体解锁（需实测） | 场景词蓝海 |
| 场景 2 | ChatGPT / AI 工具能用的低价机场 | AI 解锁（需实测） | 高意图 |
| 避坑 | 我被机场坑过的三次，以及现在的选购纪律 | 故事 + 跑路记录 | 建立信任 |
| 排障 | 订阅更新失败 / 节点全超时 的 10 步排查 | FAQ | 收藏率最高 |

**每篇必须带的三样东西**（缺一个就会被当成广告划走）：

1. 数据日期 + 数据来源（「价格取自各官网面板 2026-11-11，第三方观测已标注」）
2. 一句主动的坏话（哪家这个月不稳、哪家客服慢）
3. 「只买按月」的纪律声明

**唯一无法自动化的部分，也是你的护城河**：自己买 3~5 家月付，工作日 21:00 连测三天，记录延迟 / 晚高峰掉速 / 客服首次响应时长。这一块别人抄不走。

## 七、分发：按投产比排序

| # | 渠道 | 动作 | 预期 |
| --- | --- | --- | --- |
| 1 | GitHub 搜索 | 仓库名 + description + 12 个 topics 三层填满；**每 2~3 天一次 commit**（改优惠码、改日期都算） | 站内长尾词进前 3 页 |
| 2 | 搜索引擎收录 | Search Console / Bing Webmaster 提交 Pages 站点地图 | 2~6 周起自然流量 |
| 3 | 镜像 | Gitee / GitLab / GitCode 各一份，README 顶部互链 | 覆盖国内可达入口 |
| 4 | TG 频道 | 每天一条「今日最低价 / 新增优惠码 / 跑路通报」，全部由 `shortlist.json` 生成 | 复访率最高 |
| 5 | 长文平台 | 知乎「机场怎么选」、V2EX 讲协议不讲推广、小红书讲避坑 | 引流到仓库 |
| 6 | B 站 | 「我被机场坑了 400 块」类避坑视频 | 爆发但不可控 |

**铁律**：不刷 star、不买 star。异常增长会被判定 spam，仓库直接从搜索结果消失。

## 八、节奏与指标

| 频率 | 动作 | 耗时 |
| --- | --- | --- |
| 每 2~3 天 | `npm run data && npm run select -- --commit && npm run build` → commit | 10 分钟 |
| 每周 | `npm run probe` 刷一遍官方价；挂了的面板标 🟨 | 15 分钟 |
| 每月 | 对账返佣；删过期优惠码；补 1~2 家新机场 | 30 分钟 |
| 每季 | 按搜索下拉词改 description / topics；拆一个垂直仓库 | 1 小时 |
| 事件驱动 | 机场跑路 / 大面积通报 → 当天发通知 + 标 🟨 + 移入「已移除」 | 20 分钟 |

| 指标 | 健康值 |
| --- | --- |
| 注册点击数周环比 | 不下降 |
| 注册转化率（注册 ÷ 点击） | > 15% |
| 付费转化率（付费 ÷ 注册） | > 8% |
| 表内机场数 | 稳定 20~30 家（多了读者选不动，少了覆盖不够） |
| 返佣收入 | 第 3 个月应能覆盖自购成本 |

## 九、今天就能做的五件事

1. 打开 `data/机场选品表.xlsx`，在「① 可直接推」里挑 5~8 家，去注册并申请推广。
2. 把拿到的码填进 `data/my-aff.json`，跑 `npm run merge`，确认「用的是你的码」不再是 0。
3. 跑 `npm run probe`（在你自己的网络），把官方价刷一遍；失败的条目就是官网已挂的候选，标 🟨。
4. 自己买其中 3 家月付，今晚 21:00 各测一次速，把结果写进 `data/airports.draft.mjs` 的 `note`。
5. `npm run select -- --commit && npm run build`，把 README 发上 GitHub，填 description 和 12 个 topics。

## 十、这套东西的边界（提前想清楚，别到时候慌）

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 机场跑路 | 你推的站失联，读者来骂 | 只推按月；保留「已移除」区；表里永远有 20+ 家分散 |
| 价格过期 | 读者按你的价去买发现涨了 | `probe` 每周刷；每条标数据日期；标 📜 的写「第三方观测」 |
| 源站停更 | 你的上游断了 | 18 个源互为备份；核心 5 家自己实测兜底 |
| 仓库被下架 | GitHub 收到 abuse 报告 | 本地 git 全量备份 + 三平台镜像 + 独立站 |
| 返佣被扣量 | 后台数据和你统计的对不上 | 同时挂 5~8 家；每月对账；短链自己统计点击数 |

## 十一、第一期专题：一元机场（已落地）

数据：`data/topic-1yuan.mjs`（人工精修，12 家）　渲染：`npm run topic`　产物：`docs/topic-1yuan.md`

### 先认清一个事实：1 元档本身不赚钱

按首单 20% 返佣估算（`npm run topic -- --aff` 会打印全表）：

| 机场 | 客单价 | 单笔佣金 |
| --- | ---: | ---: |
| 多宝一元机场 | 20.99 元/年 | 4.20 元 |
| 飞鸟云 / 一元机场 | 12 元/年 | 2.40 元 |
| 良心云 | 6 元/月 | 1.20 元 |
| 一分机场 / NanoCloud | 2 元/月 | 0.40 元 |

**平均单笔佣金 1.51 元。** 就算每月 300 个注册、付费率 10%，月佣金也就 48 元。

所以这篇稿子的 KPI 不是「1 元档成交数」，而是**「从 1 元档跳到 6 元档的转化率」**。稿子结构必须为此服务：

```
标题打「一元机场」（吃搜索流量）
  ↓
第一屏结论：拆穿「1 元/月」= 年付 12 元，并给出「每 GB 成本」这个新标尺
  ↓
真·1元档（3 家）：满足搜索意图，建立「你真的用过」的信任
  ↓
伪·1元档（7 家）：这里放 6 元 1000G 的良心云 / 赔钱机场 —— 单笔佣金翻 3~6 倍
  ↓
三套现成组合：把「买哪家」变成「选哪套」，降低决策成本
  ↓
加钱升级（8~15 元档 5 家）：客单价最高的一段，用「止损」而不是「升级」来包装
```

### 三件必须做的事

1. **填码**：`data/my-aff.json` 里已经把这 10 家的主域名列好了，只需要填 `code`（和可选的 `url`）。填完 `npm run merge && npm run topic`，稿子里所有链接自动换成你的。
2. **买一轮**：至少买飞鸟云（12 元）、NanoCloud（2 元）、良心云（6 元）三家，一周后把「晚高峰能不能用」写进 `topic-1yuan.mjs` 的 `note`。**这是全文唯一别人抄不走的东西。**
3. **核两个域名**：`多宝一元机场`（tapcloud.me）和 `杏花云` 的官网没核实到，稿子里标的是「待核实」。核实到就补，核不到就保持现状——**宁可少写一家，不要导流到冒名站**，这个品类冒名站极多。

### 这个选题的天然优势

- 搜索意图极强：搜「一元机场」的人已经在掏钱了，不是在看热闹
- 竞争弱：大仓库都不屑写 1 元档（嫌佣金低），你写就是独家
- 更新成本低：一共 12 家，一家改价改一行
- 天然带「跑路预警」钩子：这个价位每季度都有站消失，每次消失都是一篇新内容 + 一次 TG 推送

### 这个选题的天花板

一个人靠 1 元档，月佣金上限大概在 100~300 元。想往上走只有三条路：

1. **把流量导到高价档**：同一批读者，在 1 元档页面里被说服买 15 元档，佣金翻 10 倍
2. **做矩阵**：1 元档、5 元档、10 元档、专线档各一个仓库/站点，覆盖不同预算的搜索词
3. **做复购**：TG 频道推「本月新增优惠码」「本月跑路名单」，让同一批人反复回来买

**1 元档是入口，不是生意。** 想清楚这一点，后面的动作才不会变形。
