**这不是一个技术项目，是一个零代码的内容资产。** 整个仓库只有两个文件：`LICENSE` 和 `README.md`（101 KB / 242 行）。没有源码、没有构建、没有部署。它靠三样东西变现：

1. **GitHub 的搜索权重**（仓库名 + description + topics + 活跃度）
2. **一篇覆盖全部长尾词的长文**（README 本身就是一个落地页）

## 六层机制（按重要性排序）

### 第一层：仓库元数据 —— 决定「能不能被搜到」

GitHub 的仓库搜索会同时命中三个字段：**仓库名、description、topics**。这个项目把三层全部塞满：

- **仓库名** `panda-vpn-pro`：直接借「熊猫VPN」这个已经存在巨大搜索量的品牌词。搜「panda vpn」的人会撞进来，然后在第一段读到「熊猫跑路了我也是受害者」——**用别人的品牌词截流，再用受害者身份完成信任转移**。这是整个项目最狠的一步。
- **description**：约 300 字，塞了 20+ 个同义词（低价机场/便宜机场/平价机场/性价比机场/一元机场/冷门机场/优质机场/廉价机场），外加客户端名（ClashForWindows、V2rayN、singbox、nekobox、小火箭）。description 是搜索结果里直接展示的摘要，关键词密度直接决定点击率。
- **topics**：12 个全部是用户真实会搜的词，一个不浪费。

### 第二层：README 长文 —— 决定「点进来会不会转化」

242 行里，真正放链接的只有 15 行表格。其余 220 多行全是**降低决策成本的内容**：

- 顶部「重要通知 / 次要通知 / 大事留档」→ 证明**还在维护**
- 作者故事（熊猫跑路、损失几百块）→ 建立**同类身份**
- 机场 vs VPN 的技术科普（加密方向不同、套壳机场）→ 建立**专业权威**
- 购前须知（🟨🔥🔒✋📜 五套标记体系）→ 制造**信息不对称的价值**：读者觉得「只有这里讲清楚了」
- 表格（开业日期/类型/倍率/套餐/优惠券）→ **决策清单**
- 排障 FAQ（订阅更新失败、DNS、IPv6）→ 提供**售后价值**，让读者收藏/回访

关键设计：**它刻意不排名**。理由是「直连/中转受本地网络影响，排名没意义」，同时避免同行攻击。真实效果是——**读者无法只买一家，只能多买几家试**，而每一家都带作者邀请码。

### 第三层：数据层 —— 决定「能不能持续产出」

表格是结构化数据的手工渲染结果：开业日期、类型、倍率、月付价、不限时价、试用、优惠券。每次机场改价、发券、出问题，只改一格。这让「每天提交」变得成本极低——**改一个字符也是一次 commit**。

本仓库的 `data/airports.mjs` + `scripts/build.mjs` 就是把这一层工程化：改数据，一条命令重排全文。

### 第四层：信任层 —— 决定「会不会被当成广告划走」

三件事同时做：

1. **受害者叙事**：先说自己被跑路坑过，再说「所以只推荐我自用的」。
2. **反向声明**：「不接受机场主投稿，不接受付费置顶，如有人以我名义联系机场主皆为冒充」。这句话同时解决「你是不是收钱」和「防同行冒充」两个问题。
3. **标记体系**：🟨 表示这家现在有问题、暂不推荐。**主动给合作方打差评**，是最高级的信任建设——它让读者相信其余没标记的是真的好。

### 第五层：时间层 —— 决定「搜索排名的持久性」

- 几乎每天 commit → GitHub 仓库排序含 `pushed_at`，搜索引擎也偏好新鲜内容。
- 每条通知都带日期（`2025.09.13`、`2026.04.24`）→ 页面里堆了上百个时间戳，**这是「长期存在」的机器可读证据**。
- 「大事留档」用 `<details>` 折叠 → 内容越积越多，但首屏不变长。

### 第六层：分发层 —— 决定「流量从哪来」

| 渠道 | 机制 |
| --- | --- |
| GitHub 站内搜索 | 元数据三层命中，搜「机场推荐」「clash 节点」都能到 |
| Google / Bing | GitHub 仓库页和 `raw.githubusercontent.com` 都被收录，且权重高 |
| 镜像 / 转载站 | 大量「机场推荐」导航站、聚合站会自动抓取 GitHub 上的高 star 仓库 |
| fork 扩散 | 439 个 fork，每个 fork 都是一个独立可被索引的副本 |
| 读者自发分享 | 「这个 GitHub 项目整理得挺全」——分享一个 GitHub 链接比分享一个博客显得更中立 |

## 变现模型（钱从哪来）

```
读者 → 点表格里的 [机场名](https://机场/auth/register?code=XXXX)
     → 注册账号（邀请码被记录）
     → 购买套餐
     → 机场按比例返佣给邀请码持有者
```

机场行业常见返佣：**首单 15%~30%，后续续费循环返 5%~15%**，部分机场有「邀请满 N 人升级比例」的分级。一家机场月流水 10 万，头部分销拿 20%，就是 2 万/月——**这就是为什么有人愿意三年不断更一个 README**。

对比另一条路（自己开机场）：需要买境外服务器、配 Xray/sing-box 后端、做面板（v2board/xboard）、抗 DDoS、抗通报、处理支付通道、7×24 客服。**成本 5 位数起步，且随时可能整站失联。**

结论：**做分销（affiliate）是投产比最高的路径，做机场主是重资产路径。** 你要做「和他一样的推广项目」，走的是第一条。

## 可复制 / 不可复制

**可以直接复制：**
- 仓库结构、README 骨架、标记体系、通知区、大事留档
- 关键词矩阵、description 写法、topics 选词
- 数据驱动的更新流程（本仓库已实现）
- 优惠券日历、跑路通报、排障 FAQ 这些「持续产出」的抓手

**不能直接复制：**
- **17,653 stars**：这是三年半 + 早期占位的结果。你现在入场，关键词前排已经被 3~5 个大仓库占住，正面硬刚不划算。
- **`panda-vpn-pro` 这个借势名字**：品牌词截流是一次性的窗口，熊猫已经跑路，这个词的搜索量在衰减。
- **先发的时间戳资产**：他 2023 年就在写「2025 年通报事件」，你补不出来。

**所以你的策略应该是：**

1. 不去抢「机场推荐」这个大词，去抢**长尾 + 场景词**（见 `data/keywords.md`）。
2. 用**结构化数据 + 自动化**打出更新频率优势（他手改，你一条命令）。
3. 用**多仓库矩阵 + 独立站**覆盖他覆盖不到的入口（他只有一个仓库）。
4. 用**更细的实测数据**做差异化（延迟/解锁/倍率实测表，他明确说不做）。

## 风险清单（操作层面，不是道德层面）

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 仓库被举报下架 | GitHub 收到 abuse 报告，仓库 404 | 本地 git 全量备份 + 同步 Gitee/GitLab/GitCode + 独立站兜底 |
| 账号被封 | 关联封禁，star 归零 | 主号只做内容，推广链接走独立短链/中转页，随时可换 |
| 机场跑路 | 你推的机场失联，读者骂你 | 只推按月、保留「已移除」区、明确写「任何机场都可能跑路」 |
| 返佣不结算 | 机场改规则、扣量 | 同时挂 5~8 家分散风险；每月对账；优先选有公开 aff 后台的 |
| 搜索降权 | 关键词堆砌过度被判定 spam | 关键词放元数据和首段，正文保持人话；别复制别人的段落 |
