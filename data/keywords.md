# 关键词矩阵

> 用法：`description` 放 A 类大词 + B 类价格词；`topics` 放 C 类技术词；README 各段落标题放 D/E 类长尾；独立站/问答放 F 类问题词。
> 优先级 ★ 越高越先做。★3 = 搜索量够大且竞争相对低，是主战场。

## F. 问题词（长尾之王，做成 FAQ 段落）

这些词搜索意图极强，几乎必然带来点击，而且大仓库往往一句话带过：

| 问题 | 做成什么 |
| --- | --- |
| 机场跑路了怎么办 | 一段「怎么判断跑路 + 怎么减少损失」 |
| 订阅更新失败 / 节点全部超时 | 10 步排查清单（README 已有） |
| 机场和 VPN 有什么区别 | 科普段（README 已有） |
| 机场倍率是什么意思 | 倍率段（README 已有） |
| 机场怎么选 / 一个月多少钱合适 | 选购决策段 |
| 为什么机场不能打游戏 | 反向内容，容易被转发 |
| 免费机场能不能用 | 风险说明（隐私/稳定性），导流到付费 |
| 机场被墙了怎么访问官网 | 官网直连/换域名技巧 |
| 订阅链接能不能分享给别人 | 「阅后即焚」机制解释 |

## 命名建议（比堆词更重要）

仓库名要满足三条：**短、能拼读、含一个高价值词**。

- ✘ `airport-recommendation-2026-best-cheap-vpn-list` —— 太长，像垃圾站
- ✔ `cheap-airport-guide` / `airport-list` / `jichang-guide`
- 借势词（如 `panda-vpn-pro`）只在有明确品牌词窗口时用，且要能自然承接（「我也是受害者」），否则显得廉价。

## description 写法模板（≤350 字符最佳）

```
{品类词} | {价格词 × 6~8 个}，{质量词 × 3~4 个}。{评测/科普词}，{场景词}。
{技术词：协议 × 4~5 个}，{节点订阅词}。适用 {客户端 × 4~5 个} 等代理软件
```

要点：
1. 前半段堆同义词（搜索引擎吃这个），后半段给**具体客户端名**（用户搜客户端名时也能命中）。
2. 不要写完整句子，不要标点过度——搜索摘要显示时会被截断，密度优先。
3. 每个季度根据 GitHub 搜索建议（在搜索框输入「机场」看下拉词）更新一次。
